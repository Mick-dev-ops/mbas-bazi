## 快速開始

需要 Node.js **22.12 或更新版本**，建議使用 Node 22 LTS。

```bash
cd mbas-bazi
npm ci
npm run dev
```

開啟終端顯示的網址。完成性別、年月日、時分、出生地選單後，按「排盤並產生完整解讀」。

```bash
npm test           # 排盤、規則、報告、介面測試
npm run build      # 產出 dist/
npm run test:dist  # 用 HTTP 驗證正式產物的儲存庫子路徑
npm run preview    # 檢視正式建置
npm run check      # 測試 → 建置 → 子路徑檢查
```

ZIP 已附本次驗證後的 `dist/`，可由靜態 HTTP 伺服器提供。不要直接雙擊 `index.html` 用 `file://` 開啟 ES module。`node_modules` 不在交付檔內，依賴由 `package-lock.json` 鎖定。

## GitHub Pages 部署

1. 在 GitHub 建立儲存庫，把本資料夾**內的全部內容**放在儲存庫根目錄，保留 `.github/workflows/deploy.yml` 等隱藏檔。
2. 儲存庫開啟 **Settings → Pages → Build and deployment → Source → GitHub Actions**。
3. 推送到 `main`。工作流程會執行 `npm ci`、測試、正式建置、子路徑檢查，再上傳 `dist` 並部署。
4. 也可從 **Actions → Test, build and deploy to GitHub Pages → Run workflow** 手動執行。
5. 部署成功後開啟 `https://帳號.github.io/儲存庫名稱/`。請以 Actions 回傳的實際網址為準。

新儲存庫的指令示意（替換帳號與儲存庫名稱）：

```bash
git init -b main
git add .
git commit -m "Build MBAS browser expert system"
git remote add origin https://github.com/帳號/儲存庫名稱.git
git push -u origin main
```

本專案 `base: './'` 產生相對資產路徑；導覽採 `#essence`、`#finance`、`#relations`、`#periods`、`#elements`、`#method`，不需要伺服器路由或 `404.html` 轉址。重新整理仍請求儲存庫根目錄的 `index.html`。出生選項僅在目前分頁以 `sessionStorage` 暫存；重新整理用目前版本重新計算，不載入舊的裁決結果。禁用儲存時仍能使用，重新整理需重填。

本次已驗證本機正式產物的 `/mbas-example/` 路徑；**沒有替使用者建立 GitHub 儲存庫，也沒有聲稱已部署到實際 GitHub 網址**。

## 排盤方法與版本

| 項目     | 本版                                       |
| -------- | ------------------------------------------ |
| 排盤     | `ziping-solar-1.0.0`                       |
| 解讀規則 | `mbas-1.1.0`                               |
| 文字模板 | `zh-TW-1.1.0`                              |
| 天文計算 | `astronomy-engine 2.1.19`                  |
| 法定時區 | `moment-timezone 0.6.0`，內附 IANA `2025b` |
| 出生年   | 1901–2026（含首尾）                        |
| 大運     | 十步、每步十個曆年                         |
| 流年     | 出生所屬干支年起，至出生西元年後 110 年    |

- **年柱**：以太陽視黃經 315° 的立春實際數值交接時刻為界，非農曆正月初一。
- **月柱**：以十二節：立春、驚蟄、清明、立夏、芒種、小暑、立秋、白露、寒露、立冬、大雪、小寒為界。依年干起寅月月干。中氣保留在節氣資料中，但不用於起月或起運。
- **日柱**：出生地法定當地曆日，00:00 換日；以公曆日序對應六十甲子。1970-01-01 為辛巳、2000-01-07 為甲子，另以香港天文台 2024-03-05 戊辰日作外部回歸案例。
- **時柱**：法定時間 23:00–00:59 為子時。23:00–23:59 使用當日的日干；次日 00:00–00:59 使用次日的日干，不採 23:00 換日。不修正經度、均時差或真太陽時。
- **時區**：固定資料隨 bundle 打包，不依賴訪客作業系統的 `Intl` 時區版本。將當地法定出生時間反解為 UTC 後，與天文交節時刻比較。跳時造成的不存在時間與回撥造成的重複時間皆拒絕，要求核對出生紀錄，不擅自選擇一次。
- **精度**：天文求根時間為數值近似，秒數不是準確度保證；2024 立春與驚蟄以公開分鐘曆表在 ±120 秒內作外部核對。尚未逐一對照 1901–2026 的全部節氣。接近交節時，出生紀錄的分鐘精度與天文近似均可能影響分界。

### 大運起算與進位

陽男、陰女順行；陰男、陽女逆行。順行取下一個節，逆行取上一個節。精確落在節點時，「上一個節」包含當下節點，「下一個節」嚴格晚於當下。

```text
gapDays = |節時刻UTC − 出生UTC| / 86400000
起運總秒 = round(gapDays × 120 × 86400)
```

以每年 360 日、每月 30 日將起運總秒拆為年、月、日、剩餘秒。這使三日折一年、一日折四個月；不足一日照比例換算至秒，再四捨五入。依序加出生地的曆年、曆月、日、秒；月底超出者收至月底，採 Moment 的曆法加算語義。

第一次交運後，第 n 步起點直接由首次交運時刻加 `(n−1)×10` 曆年，不以固定 3650 日代替十年。起迄採 **[起點, 下一步起點)**，同一瞬間不會同屬兩步。流年採立春到下一立春；跨交運時刻會分段。立春前出生者可選上一個西元標示年，起點截至出生時刻。

### 工程化規約與邊界

這份程式是**公開條件的規則實作**，不是聲稱獲古籍認證或已驗證預測準確度的模型。需求所列方法不是唯一數值標準；本專案將缺少統一門檻的地方明訂為下列版本化規約，方便檢查、測試與日後替換：

- 藏干權重：單藏 1；雙藏 .7/.3；三藏 .6/.25/.15。月柱藏干乘 1.5。季節旺／相／休／囚／死為 1.5/1.25/1/.8/.65。土月按月支本氣土處理，沒有另外細分土王用事日數。
- 非日主天干：有同五行根乘 1.15、無根乘 .65；根有無與根受制程度分別保留。合剋刑害對係數按規則表折減。原局依柱距判斷可達性；歲運為期間力量，可直接作用於全盤各柱。日干本身不再當天干比肩重複計數。
- 組合十神力量以聚合值 ≥.8 判參與；位置承接需參與個體力量 ≥.2，且柱位相鄰或同柱、個體不同。這是簡化的位置連接，沒有建構所有傳統隔干、藏干引動學說。
- 個別十神項目 ≥.8 標「達可用門檻」，不足者標「表見／需承接」。這與聚合十神力量是兩個不同層級。
- 承格採 `印比支持 × 得令係數 / 財官食傷負荷`；≥1.2 為可承、≤.85 為承格不足，中間需配合。得令係數與盤面作用力分開，屬本模型的額外季節校驗。
- 天干相合先折減牽制；即便符合保守化氣條件，也只標候選，**不改寫日主或五行**。三合三會亦只記完整候選，不自動化局。沖刑對相關地支的根統一折減，沒有聲稱逐個藏干都採古法的拔根／開庫裁決。
- 調候 120 格是由寒月亥子丑、熱月巳午未、燥土未戌、濕土丑辰四類規約生成，日干用於對應功能、透根承接及後續裁決；**不是逐條採錄《窮通寶鑑》的十干逐月專條**。
- 未實作從格、專旺格、化氣改盤、半合成局、神煞、納音、胎元命宮、紫微、六爻或真太陽時。複雜命局不應被理解為這些規則已完整涵蓋。
- 病藥與作用力仍含工程化門檻；喜忌採結構救應序位而非累計功能分，均為可重現判斷，不是事件發生機率。相神為結構需要的作用；是否足力及是否有副作用另行檢查。
- 傳統配偶星以男性取財、女性取官殺作規則框架，文字不預設伴侶性別或性傾向；不據此宣稱婚姻或財富結果。
- 實際補法提供行為與生活節律的類比，顏色、方位、材質、飾品另列傳統象徵，沒有宣稱能物理改變命盤或驗證現實療效。健康限生活節律及耗損模式。

## 檔案與維護分工

```text
.github/workflows/deploy.yml  main 推送及手動部署
src/calendar/                法定時間、節氣、四柱、大運
src/data/constants.js        干支、五行、藏干、十神、版本
src/data/locations.js         出生地與年代支援範圍
src/data/timezones.json      固定歷史時區（由腳本生成並納入版本控制）
src/data/rules.js             規則編號、版本、條件、排除、適用頁
src/data/climate.js           日干×月令調候索引
src/engine/                  事實、互動、格局、承格、病藥、流通、裁決、歲運
src/report/                  情境文字模板、五頁生成、一致性檢查
src/ui/                      HTML 呈現與證據展開
src/main.js                  表單、頁籤、流年互動、列印、JSON
src/style.css                桌機、手機、列印樣式
scripts/                     正式產物子路徑檢查、時區資料擷取
 tests/                      曆法、規則、報告與 DOM 測試
 docs/                       規則索引、架構與驗證紀錄
 dist/                       本次正式建置（交付 ZIP 附帶，Git 預設忽略）
```

修改規則請同時更新 **規則條件、執行邏輯、正反測試、規則版本**；修改排盤慣例或時區資料請更新排盤版本與外部核對案例；修改模板請更新模板版本。不要在 `ui/` 中另寫一套喜忌判斷。JSON 匯出含結構化中間結果、規則 trace、五頁報告及所選流年，schema 為 `mbas-report-1.0.0`；函式本身不序列化。

`npm run format` 格式化原始碼；`npm run format:check` 檢查格式。本專案以可讀的 ES modules 編寫，無框架後端耦合。

## 測試與確認範圍

本次實際執行結果見 [驗證紀錄](docs/TEST_RESULTS.md)。測試涵蓋：

- 紐約冬夏、DST 缺口與重複、臺灣 1979 歷史 DST、全部支援地點。
- 大運四種順逆、只取節、起運秒換算、月底收斂、十年連續區間、精確交運與流年分段。
- 十神藏干、透根季節、合剋沖刑害、化氣候選正反條件、完整三合及缺字排除。
- 五種組合正反例、力量不足、位置隔絕、梟印／財破印／承格排除、月令優先與相神不足。
- 得令得地得勢、主病與救應副作用、源流通關及真假、調候索引與全局承接、喜忌角色與順序。
- 不同出生資料的不同四柱與報告、相同輸入的確定性、五頁一致性、每項結論的規則追溯。
- 表單連動、五頁切換、流年互動、列印五主題、JSON 下載、錯誤回報與方法頁。

桌面 Chrome 已人工操作抽查首頁、生成命盤、頁籤與依據展開。手機採響應式與橫向可捲時間軸／表格；未在實體手機逐機測試。DOM 測試不等於真實列印機或所有瀏覽器的視覺測試。GitHub Actions workflow 已提供並檢查，實際雲端執行仍需放入使用者儲存庫後觸發。
