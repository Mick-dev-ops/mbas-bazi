# 1.8.0 多條件敘事與五行情境化修正

## 問題、原因與修改

| 使用者看到的問題           | 原程式原因                                                 | 本次修改                                                                                                             |
| -------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 不同命盤的本質總評近似     | 總評只取月令十神的一句優點，再接固定人生勸告               | 同時使用月令主題、日支內在反應、輔助傾向、承載狀態與主要失衡組句，並把日常反應、壓力反應與人生調整寫成同一條可讀主線 |
| 各頁內容有罐頭感           | 顯示層大量使用單一分類模板，沒有把不同計算結果轉成不同情境 | 擴充規則式文案庫，讓財務、關係、行運與五行總評帶入各自已算出的機制、位置、期間與優先順序                             |
| 五行頁出現兩個總評         | 頁面置頂總評之外，卡片陣列又加入一張整體總評               | 移除重複卡片；頁面只保留一個五行總評，其後直接進入今年調整與五張五行卡                                               |
| 五行說明充滿十神與格局術語 | 當期引擎的內部診斷、救應與十神字串被直接搬到公開報告       | 顯示層不再輸出內部裁決字串；依五行對本命的實際功能，轉為自主分工、表達創作、金錢時間、承諾界線、理解休息五類生活情境 |
| 「過少」沒有說明本人會怎樣 | 只寫哪條生剋鏈受損，沒有行為與生活結果                     | 每一類都新增過少、適中、過多、使用前、使用後、實際做法與四週／每月核對指標                                           |

語言模型只用於本次開發時協助撰寫與校對情境文案；這些內容已固定在程式的條件分支中。網站執行時仍是瀏覽器端規則運算，不串接AI、後端或API金鑰，也沒有針對特定姓名、生日或四柱寫例外。

## 修改檔案

- `src/report/life-story.js`：多軸本質總評、壓力情境與轉向方式。
- `src/report/templates.js`：五種功能關係的具體生活情境、做法與驗證指標。
- `src/report/client.js`：移除重複五行總評、隔離內部術語、組合原局與當期生活描述。
- `tests/client-report.test.js`、`tests/period-context.test.js`、`tests/rule-audit-140.test.js`：更新顯示層契約與公開術語檢查。
- `README.md`、`docs/TEST_RESULTS.md`、`docs/UPGRADE_WINDOWS.md`：版本與交付說明。

## 驗證範圍

- 抽樣不同年份、月份、日期、時辰與性別的15張命盤，本質總評為15種不同組合。
- 每張五行頁只有一個置頂總評、一張今年調整卡與五張五行卡。
- 公開五行頁不含十神、格局、主病、相神、承格及作用力等內部術語。
- 正式建置與正式產物DOM另行檢查；依使用者要求不執行完整 `npm test`。

## 驗收提醒

規則式系統的差異來自多個命盤條件的組合，不是為每一組四柱預存一篇文章。相同結構與相同作用可以出現相同的局部建議，但總評與當期結論必須隨實際條件改變。請在網站以數張結構差異明顯的命盤交叉驗收，並以手機確認五行頁的長文閱讀與列印分頁。
