# 1.3.0 運年情境模型與涵蓋範圍

本版修正的根因：1.2.0 閱讀層只把運年縮成少數推進或整理桶，忽略原本已計算的多數互動。不同運年因此落入同一段文字。這不只是字詞重複，而是決定內容的條件不足。

## 語義組合

1. `data/period-scenes.js`：十神各有不同的工作／學習／熟齡／關係功能，陰陽正偏不混成一個句子。
2. 十神保留十種功能，另以五類功能建立 25 個有方向的配對關係；十乘十共有100種功能配對入口。
3. 保留已實作的五個組合格局與十種月令結構描述，共15類結構入口。這不是所有古典特殊格局的全集。
4. `engine/period-context.js`：把大運與流年干支實際加入原局，重新建立作用後事實、承接、格局、病藥、流通、調候與候選救應。本命喜忌獨立保留。
5. `report/period-story.js`：同時使用運年天干、本氣及其他藏干、原局主線、本期病藥、真正受作用柱位與年齡，形成情境。日干參與作用不被誤寫為夫妻宮事件。
6. `report/client.js`：按實足歲與交運分段；財運與大運均可選擇一運，再讀其中每一年的完整時間段。

沒有隨機換詞、按年份輪替句子或用雜湊挑選文案。相同條件產生相同內容；相近條件可能有共同的本命限制，但運年功能、作用位置與生活領域會分開說明。

## 當期五行

預設參考年由臺北當下日期與立春邊界決定；使用者可以切換年份。遇交運或人生階段邊界，保留分段。五行頁顯示本命使用順序及本期優先順序，不覆寫本命喜忌。

本期優先依具體病藥候選、可用救應與本命限制整理。只有明確根氣破壞或實際調候阻礙才容許短期的條件例外。逐一說明木火土金水已隨哪個運年進入、增加後先影響什麼、與當期力量的承接或牽制、適量狀態與過量代價。這是命理功能假說，不是生活行為可改變出生四柱的物理模擬。

## 姻緣與子女

第三章不含商業合作。相遇與承諾窗口至少結合關係功能、日常相處宮位或表達／接觸訊號，不能單憑一個合沖指定婚期。子女部分結合時柱、表達與照顧功能及歲運，呈現家庭規劃、教養與照顧分工；不指定子女數量、性別、懷孕或健康。桃花在本版指接近與吸引情境，未新增冒稱已校準的神煞算法。
